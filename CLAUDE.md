# CLAUDE.md — Руководство для AI-ассистента

## Описание проекта

**Репозиторий:** `Kedros64/telegram-channel-land-water`

Этот репозиторий обеспечивает автоматизацию **Telegram-канала о земельном и водном праве России**.

### Тематика канала

Канал публикует:
- Изменения в земельном и водном законодательстве
- Оформление водопользования, гидротехнических сооружений (ГТС), прудов, водоёмов
- Аренду и оформление земельных участков
- Судебную практику по земельным и водным спорам
- Абсурдные и показательные бюрократические кейсы из этой сферы

### Бизнес-цель

Привлечение клиентов на услуги по оформлению водопользования, гидротехнических сооружений, земельных участков и всего смежного. Автор канала — консультант в этой сфере.

### Аудитория

Предприниматели, фермеры, арендаторы, управленцы, владельцы участков и водоёмов — люди которым важно: «что это значит для меня на практике».

## Описание скриптов

### scripts/monitor.py

**Задача:** Мониторинг источников, двухэтапная фильтрация и генерация постов.

**Алгоритм:**
1. Проверяет наличие `GEMINI_API_KEY` — завершает работу если не установлен
2. Читает `sources.xlsx`, фильтрует строки с `active = да`
3. Собирает статьи со **всех** активных источников без тематической фильтрации:
   - тип `telegram` — парсит публичный веб-вид канала через `https://t.me/s/{channel}`
   - тип `site` — сначала пробует RSS/Atom-фид, при неудаче — HTML-парсинг с CSS-селекторами
   - Пауза 1 сек между запросами к сайтам (вежливый краулер)
4. **Пре-фильтрация по ключевым словам** — быстро отсекает заведомо нерелевантное до Gemini
5. **Финальная фильтрация через Gemini API** — отправляет заголовки батчами по 80 штук, получает JSON с `relevant_ids`; при недоступности Gemini — fallback на keyword-фильтрацию
6. Генерирует пост через Gemini API для каждой релевантной статьи (до `MAX_POSTS_TO_GENERATE = 3`); пауза 2 сек между вызовами
7. Сохраняет результат в `posts/ГГГГ-ММ-ДД_ЧЧ.md`
8. Обновляет `posts/last_check.txt`

**Переменные окружения:**
- `GEMINI_API_KEY` — ключ Google Gemini API (обязателен)

**Ключевые константы:**
| Константа | Значение | Описание |
|---|---|---|
| `GEMINI_MODEL` | `gemini-2.0-flash` | Модель для фильтрации и генерации |
| `MAX_ARTICLES_PER_SOURCE` | `10` | Максимум статей с одного источника |
| `MAX_POSTS_TO_GENERATE` | `3` | Максимум постов за один запуск |
| `FILTER_BATCH_SIZE` | `80` | Заголовков в одном запросе к Gemini |
| `generationConfig.temperature` | `0.7` | Температура генерации |
| `generationConfig.maxOutputTokens` | `2048` | Лимит токенов ответа |

**Особенности:**
- Если источник недоступен — логирует предупреждение и продолжает с остальными
- SSL-верификация отключена (`verify=False`) — многие госсайты РФ имеют самоподписанные сертификаты
- User-Agent имитирует браузер Chrome — снижает риск блокировки
- При ошибке 429 от Gemini — до 3 повторных попыток с задержкой 5/10/20 сек
- Пре-фильтрация по ключевым словам срабатывает до отправки в Gemini (уменьшает батч)

**RSS-поиск для сайтов** (`_try_rss`):
Проверяет сам URL и 9 стандартных путей: `/rss`, `/rss.xml`, `/feed`, `/feed.xml`, `/atom.xml`, `/news/rss`, `/news/feed`, `/export/rss`, `/lenta/rss`. Парсит RSS 2.0 и Atom через stdlib `xml.etree.ElementTree`.

**HTML-парсинг** (`_try_html`):
Перебирает 20 CSS-селекторов (`article`, `.news-item`, `.news__item`, `.card`, и др.); если ни один не дал ≥3 блоков — fallback на заголовки `h2`/`h3`/`h4` со ссылкой.

### scripts/poster.py

**Задача:** Публикация готовых постов в Telegram-канал.

**Алгоритм:**
1. Сканирует `posts/*.md` — берёт файлы без суффикса `_posted` и не в `posted.log`
2. Извлекает блоки `**ГОТОВЫЙ ПОСТ:**` регуляркой
3. Очищает текст (`sanitize_for_telegram`): удаляет управляющие символы, обрезает до 4096 символов
4. Конвертирует Markdown-разметку в HTML (`markdown_to_html`):
   - `[текст](url)` → `<a href="url">текст</a>`
   - `**текст**` → `<b>текст</b>`
   - `*текст*` → `<i>текст</i>`
   - `` `текст` `` → `<code>текст</code>`
5. Отправляет каждый пост через `sendMessage` (Telegram Bot API, `parse_mode=HTML`)
6. При ошибке разбора HTML — повторяет без `parse_mode`
7. Между постами из одного файла — пауза 30 секунд
8. При успехе: переименовывает файл (`_posted.md`) и записывает в `posted.log`
9. При ошибке: записывает в `errors.log`, продолжает со следующим файлом

**Переменные окружения:**
- `BOT_TOKEN` — токен Telegram-бота
- `CHANNEL_ID` — ID или @username канала

Хранится в корне репозитория. Лист: **Sources**. Текущее количество активных источников: **51**.

| Столбец  | Описание                              |
|----------|---------------------------------------|
| `name`   | Название источника (для отображения)  |

```markdown
---

## Пост 1

**Источник:** Название источника — https://example.com/article
**Суть:** Заголовок материала

**ГОТОВЫЙ ПОСТ:**
Текст готового поста (800–1500 символов)

**ВАРИАНТЫ CTA:**
Нейтральный: [вариант]
С юмором: [вариант]
Прямой: [вариант]

**ВИЗУАЛ:**
Prompt (EN): [промпт для Midjourney/DALL-E, flat design или editorial cartoon, 16:9, no text in image]
Описание (RU): [2–3 слова]
Запасной вариант: [упрощённый промпт]
```

При отсутствии материалов:
```markdown
# Мониторинг ГГГГ-ММ-ДД ЧЧ:ММ
Проверено источников: N
Найдено релевантных материалов: 0
```

## Критерии релевантности

### Двухэтапная фильтрация

**Этап 1 — Keyword pre-filter** (быстрая проверка, без API):
Статья проходит если `title + content` содержит хотя бы одно ключевое слово **И** не содержит стоп-слов.

**Ключевые слова** (поиск по подстроке, нижний регистр):

`земельн`, `водн`, `гтс`, `пруд`, `кадастр`, `росреестр`, `росводресурс`, `рослесхоз`, `роснедр`, `минприрод`, `росприроднадзор`, `аренда земли`, `межеван`, `сервитут`, `водоохранн`, `экологическ`, `лесфонд`, `недр`, `водопользован`, `водоём`, `водоем`, `береговая полоса`, `гидротехнич`

**Жёсткие стоп-слова:** `убийство`, `теракт`, `наркотики`

**Этап 2 — Gemini API filter** (точная семантическая фильтрация):
Gemini получает пронумерованный список заголовков и возвращает JSON `{"relevant_ids": [1, 3, 5]}`. При недоступности Gemini — используется только результат keyword pre-filter.

## Тон и стиль канала

- Лёгкий, немного хулиганский, с аккуратным юмором — без хамства и токсичности
- Подшучиваем над **ситуациями** и бюрократией — **не над людьми и организациями**
- Язык живой, без канцелярита; никаких юридических гарантий
- Формулировки: «как правило», «по практике», «есть риск что», «по сложившейся практике»
- Если материал о конкретном регионе — упоминаем регион
- Если упомянут нормативный акт — обязательно называем его
- В конце подходящих постов — ненавязчивое упоминание, что автор канала занимается оформлением

## Настройка автопостинга

### Шаг 1: Создать Telegram-бота и получить BOT_TOKEN

1. Открой [@BotFather](https://t.me/BotFather) в Telegram
2. Отправь команду `/newbot`
3. Придумай имя бота (например: `Land Water News Bot`) и username (например: `landwaterbot`)
4. BotFather пришлёт `BOT_TOKEN` в формате `1234567890:ABCdef...`
5. Сохрани токен — он понадобится на шаге 4

### Шаг 2: Добавить бота администратором канала

1. Открой настройки своего Telegram-канала
2. Перейди в **Администраторы → Добавить администратора**
3. Найди своего бота по username
4. Включи право **«Публикация сообщений»** (остальные можно отключить)
5. Сохрани изменения

### Шаг 3: Узнать CHANNEL_ID

- **Публичный канал:** CHANNEL_ID = `@username_канала` (например, `@my_land_channel`)
- **Приватный канал:** перешли любое сообщение из канала боту [@userinfobot](https://t.me/userinfobot) — он покажет числовой ID в формате `-1001234567890`

### Шаг 4: Получить Google Gemini API Key

1. Перейди на [aistudio.google.com/app/apikey](https://aistudio.google.com/app/apikey)
2. Нажми **Create API Key**
3. Скопируй ключ (начинается с `AIza...`)

### Шаг 5: Добавить секреты в GitHub

1. Открой репозиторий на GitHub
2. Перейди в **Settings → Secrets and variables → Actions**
3. Нажми **New repository secret** и добавь по одному:
   - `GEMINI_API_KEY` — ключ от Google Gemini
   - `BOT_TOKEN` — токен Telegram-бота
   - `CHANNEL_ID` — ID или @username канала

### Шаг 6: Протестировать

1. Перейди в **Actions → Monitor and Post**
2. Нажми **Run workflow → Run workflow**
3. Наблюдай за логами — должны пройти шаги:
   - `Run monitor` — появится файл `posts/ГГГГ-ММ-ДД_ЧЧ.md`
   - `Post to Telegram` — посты появятся в канале
   - `Commit post results` — в репозитории файл переименуется в `_posted.md`

### Шаг 7: Локальное тестирование

```bash
# Клонировать репозиторий
git clone https://github.com/Kedros64/telegram-channel-land-water.git
cd telegram-channel-land-water

# Установить зависимости
pip install -r requirements.txt

# Создать .env из примера и заполнить токены
cp .env.example .env
nano .env

# Запустить мониторинг
python scripts/monitor.py

# Опубликовать посты
python scripts/poster.py
```

## Расширение источников

Чтобы добавить новый сайт для мониторинга:

1. Открой `sources.xlsx` (Excel / LibreOffice Calc)
2. Добавь строку в лист **Sources**:
   - `name` — понятное название (например: `Судебные акты ВС РФ`)
   - `url` — прямая ссылка на страницу со списком новостей/публикаций
   - `type` — `site`
   - `active` — `да`
3. Сохрани и закоммить: `git add sources.xlsx && git commit -m "Add new source: ..."`

**Совет:** Указывай ссылку на страницу с **архивом/списком** новостей, а не на главную страницу сайта. Например: `https://rosreestr.gov.ru/press/archive/` вместо `https://rosreestr.gov.ru/`.

Чтобы добавить **Telegram-канал** для мониторинга:

1. Добавь строку в `sources.xlsx`:
   - `url` — `https://t.me/channelname` или просто `@channelname`
   - `type` — `telegram`
   - `active` — `да`
2. Работает только для **публичных** каналов (видны через `t.me/s/channelname`)
3. Для приватных каналов — потребуется MTProto API (см. ниже)

## Мониторинг Telegram-каналов

### Публичные каналы (работает из коробки)

`monitor.py` парсит публичные Telegram-каналы через веб-интерфейс `https://t.me/s/{channel}` без каких-либо API-ключей. Реализовано в функции `fetch_telegram_channel()`.

- Извлекает до `MAX_ARTICLES_PER_SOURCE = 10` последних сообщений
- Пропускает посты без текста (только фото/видео)
- Минимальная длина текста — 30 символов
- Ссылка на каждое сообщение берётся из атрибута `href` элемента `.tgme_widget_message_date`

### Приватные каналы (требует MTProto API)

Для мониторинга приватных каналов нужна авторизация через Telethon:

1. **Зарегистрируйся на [my.telegram.org](https://my.telegram.org)** — нужен номер телефона
2. **Создай приложение** → получи `API_ID` (число) и `API_HASH` (строка)
3. **Установи Telethon:** добавь `telethon>=1.36.0` в `requirements.txt`
4. **Добавь переменные в `.env` и GitHub Secrets:**
   ```
   TELEGRAM_API_ID=12345678
   TELEGRAM_API_HASH=abc123def456...
   TELEGRAM_SESSION=base64_encoded_session_string
   ```
5. **Замени** функцию `fetch_telegram_channel()` в `scripts/monitor.py` на реализацию через `TelegramClient`

## Ключевые решения

| Решение | Обоснование |
|---|---|
| Двухэтапная фильтрация (keyword + Gemini) | Keyword pre-filter быстро отсекает явный мусор; Gemini делает точный семантический отбор |
| RSS-first для сайтов, HTML как fallback | RSS структурирован и надёжен; HTML-парсинг охватывает сайты без RSS |
| Gemini API фильтрует батчами по 80 заголовков | Минимум API-вызовов при большом пуле статей |
| Парсинг t.me/s/ для публичных Telegram-каналов | Работает без API-ключей и MTProto; достаточно для публичных каналов |
| Google Gemini API для генерации постов | Быстрая генерация; модель `gemini-2.0-flash`; retry на 429 |
| HTML parse_mode в Telegram | Надёжнее MarkdownV2 — меньше проблем с экранированием спецсимволов |
| `sanitize_for_telegram()` перед отправкой | Удаляет управляющие символы; обрезает до 4096 символов |
| Переименование в `_posted.md` | Состояние публикации видно в git-истории; не зависит от внешних файлов |
| Пауза 30 сек между постами | Предотвращает флуд-фильтр Telegram и не раздражает подписчиков |
| SSL `verify=False` | Многие госсайты РФ используют самоподписанные или устаревшие сертификаты |
| `last_check.txt` в git | Состояние проверки сохраняется между запусками workflow |

## Что нельзя делать

- Не коммить `.env` — только `.env.example`
- Не хардкодить токены и ключи в коде
- Не пушить напрямую в `main`
- Не удалять `posts/last_check.txt` — это сломает отслеживание новых публикаций
- Не менять формат блока `**ГОТОВЫЙ ПОСТ:**` без обновления регулярки в `poster.py`
